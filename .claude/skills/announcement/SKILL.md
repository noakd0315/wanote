# お知らせ作成

wanote のアプリ内お知らせを、**日本語の文面から登録内容まで**組み立てる。

PMは英語が書けない。だから英語版はこちらが用意し、**その英語が何と言って
いるかを日本語に訳し戻して見せる**。訳し戻しが無いと、PMは自分の名前で
出す文面の意味を確認できないまま公開することになる。これがこのスキルの
中心にある考えで、省略してはいけない。

---

## 進め方

**一度に全部聞かない。1問ずつ確認しながら進める。** PMは運用の片手間に
これを使う。長い質問票を出されると、その場で答えられない項目で止まる。

各ステップで答えを受け取ったら、次に進む前に**短く復唱**する。

### ステップ1：何を知らせるか

まず日本語の文面を聞く。**見出しと本文を一度に受け取ってよい**（ここは
1問扱い）。

> どんなお知らせを出しますか。日本語で、見出しと本文を教えてください。
> 箇条書きやメモ書きでも構いません。こちらで整えます。

文面が荒くても書き直しを求めない。整えるのはこちらの仕事。ただし
**日付・時刻・金額・機能名は勝手に変えない**。事実を含む部分は原文のまま
扱い、変えたい場合は確認する。

### ステップ2：重要度

> このお知らせは **サインインしていない人にも見せますか。**
>
> - **いいえ**（通常）… ホームのバナーと、設定→お知らせに出ます
> - **はい**（重要）… 上に加えて**サインイン画面にも**出ます

「はい」と言われたら、一度だけ確認する。

> 重要にすると、アプリを開いた誰にでも最初に見えます。**サインインできない
> 障害のとき向け**の設定です。今回はその状況ですか。

平常時のお知らせに `important: true` を付けると、初回利用者が最初に見る
画面に常時何かが出ている状態になり、離脱要因になる。ここは押し返してよい。

### ステップ3：いつまで出すか

> **いつまで表示しますか。** 日付を教えてください。

`expires_at` は**必ず入れる**。省略を認めない。「ずっと出しておきたい」と
言われた場合も、期限を切るよう促す。

> 期限のないお知らせは、消し忘れると誤った案内を出し続けます。たとえば
> 「8/13〜8/20 は問い合わせをお休みします」が残っていると、営業している
> のに休業中と表示されます。**長めでも構わないので期限を決めてください**
> （例：3か月後）。

告知期間が文面に含まれる場合（「8/25 2:00〜4:00」など）、**その終わりの
少し後**を提案する。メンテナンス終了と同時に消えると、終わったことに
気づけない人が出る。

### ステップ4：いつから出すか

> **いつから出しますか。** すぐで良ければ「すぐ」と答えてください。
> 予約したい場合は日時を教えてください。

「すぐ」なら `published_at` は作成時刻。予約なら指定日時。

### ステップ5：英語版を作って見せる

日本語を整え、英語に訳す。**訳したら必ず、その英語の意味を日本語に訳し
戻して並べる。**

英語は**直訳しない**。飼い主が読む短い告知として自然な英語にする。
日本語の告知にありがちな前置き（「平素より格別のご高配を賜り」など）は
英語では省く。残すと不自然で、かえって読まれない。

提示のしかた:

```
【日本語】
見出し: アプリを更新しました
本文:   予防医療の記録で…

【英語】
Title: App updated
Body:  Preventive care records now ask…

【英語の意味（訳し戻し）】
見出し: アプリを更新しました
本文:   予防医療の記録が、それぞれのケアに必要なことを聞くようになりました…
```

そのうえで聞く。

> 英語の意味はこれで合っていますか。直したいところがあれば教えてください。

**「訳し戻し」は逐語訳にする。** 元の日本語をそのまま再掲すると検証に
ならない。英語だけを読んで日本語に起こす。

### ステップ6：登録内容を出す

確認が取れたら、**コンソールに貼れる形**で出す。

コレクション: `announcements` / ドキュメントID: **自動ID**

| フィールド | 型 | 値 |
|---|---|---|
| `title_ja` | string | （見出し・日本語） |
| `body_ja` | string | （本文・日本語） |
| `title_en` | string | （見出し・英語） |
| `body_en` | string | （本文・英語） |
| `published_at` | timestamp | （日時） |
| `expires_at` | timestamp | （日時） |
| `important` | boolean | `true` / `false` |

**型を間違えると意図どおり動かない。** 日付は timestamp、`important` は
boolean。コンソールの型プルダウンで選ぶよう添える。

最後に手順を添える:

> Firebase コンソール → Firestore Database → `announcements` →
> 「ドキュメントを追加」→ ドキュメントIDは「自動ID」→ 上の7フィールドを
> 入力 → 保存
>
> 保存した時点で、アプリ側は**次回の画面表示から反映されます**。
> 再ビルドもアプリの更新も要りません。

## 知っておくこと

### 登録は必ずPMが行う

`announcements` は Firestore のルールで**アプリからの書き込みを禁止**して
いる（`firestore.rules` の `match /announcements/{id}` は `allow write: if false`）。
自分でお知らせを投稿できるアプリは、そのお知らせが信用できないため。

**書き込みを代行しない。** サービスアカウントの鍵はこちらに渡さない
取り決めになっている。組み立てた内容を渡し、PMがコンソールに入れる。

### 英語版が無くても壊れない

`title_en` / `body_en` は任意。無ければ英語表示でも日本語が出る
（`lib/shared/models/announcement.dart` の `titleFor` / `bodyFor`）。
急ぎのときは日本語だけで先に出し、英語を後から足す運用も取れる。
**ただしこのスキルを使う以上、英語版まで作り切る。**

### 表示される場所

| | 出るもの |
|---|---|
| ホームのバナー | 表示期間内のもの（閉じられる。開き直すと再表示） |
| 設定 → お知らせ | 表示期間内のものすべて |
| サインイン画面 | `important: true` のものだけ |

### 削除

ドキュメントごと消せば消える。期限切れは自動的に見えなくなるので、
**急ぎでなければ消さなくてよい**。

---

## やってはいけないこと

- **日付・時刻・金額・機能名を勝手に変える。** 事実を含む部分は原文のまま
  扱い、変えるなら確認を取る。
- **訳し戻しを省く。** PMが英語を検証できる唯一の手段。
- **`expires_at` を空のまま出す。** 消し忘れは誤った案内になる。
- **平常時のお知らせに `important: true` を付ける。**
- **コンソールへの書き込みを代行する。**
