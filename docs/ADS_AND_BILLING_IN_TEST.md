# 広告とRevenueCatは、テスト段階でどこまでやるか

作成: 2026-08-18
関連: `RECRUITMENT_9_1_PLAN.md`, `PLAN_ads.md`

**結論（逆向きです）:**

| | クローズドテストで | 理由 |
|---|---|---|
| **広告（AdMob）** | **テストユニットのまま**にする | 本番ユニットは**アカウント停止のリスク**。しかも未公開アプリには配信されにくい |
| **RevenueCat（課金）** | **本番と同じ設定で試す** | **課金フローを無料で試せるのはテスト期間だけ** |

---

# 1. 広告（AdMob）

## 🔴 クローズドテストで本番の広告ユニットを使わないでください

**テスターが広告をタップすると「無効なトラフィック」と判定され、
AdMobアカウントが停止される可能性があります。**

- 身内・知人によるタップは、Googleが最も厳しく見る類型です
- 停止されると**復旧は難しく**、収益手段を失います
- テスト期間中の収益はどのみちほぼゼロです

**リスクだけを取る形になるので、やめてください。**

## 現状：何もしなければ安全です

`config/prod.json` に AdMob の項目が入っていないため、
**Googleの公式テストユニットが使われています**。

```
ADMOB_INTERSTITIAL_ANDROID / _IOS
ADMOB_BANNER_ANDROID / _IOS      ← すべて未設定 = テストユニット
```

**テスト広告は本物と同じタイミング・同じ見た目で出ます。**
表示位置、閉じたあとの復帰、プレミアム時に出ないこと——
**広告まわりの確認はテストユニットで全部できます。**

## それでも今やっておくこと（待ち時間があるため）

| やること | なぜ今か |
|---|---|
| AdMobアカウント作成 | ストア未公開でもアプリ登録できます |
| 広告ユニット作成 → ID控え | 公開時にすぐ差し替えられる |
| **支払い情報・税務情報の登録** | **確認に時間がかかる**。収益を受け取る前提条件 |
| app-ads.txt の準備 | 公開後に必要 |

> **AdMobの「アプリ承認」はストア公開が前提です。** 未公開アプリは
> 広告配信が制限されるため、テスト中に本番ユニットを入れても
> **そもそもまともに配信されません。**

## 🔴 私に渡してはいけないもの / 渡すもの

- **広告ユニットIDは推測で書きません。** 必ずPMが控えた実物をください
- **アプリID**（`ca-app-pub-xxxxx~yyyyy`）だけは
  `AndroidManifest.xml` と `Info.plist` に書く必要があります
  （OSがDartより先に読むため）。**公開ビルドの直前に私が入れます**

# 2. RevenueCat（課金）

## こちらは、テスト期間が本番を試せる唯一の機会です

| | 課金テスト |
|---|---|
| **Android** | **ライセンステスター**に登録した人は**請求なし**で購入できる。サブスクの更新も高速化される |
| **iOS** | **TestFlightの購入は自動的にSandbox**。実際の請求は発生しない |

**公開後に初めて課金を試すのは危険です。** 決済は失敗の仕方が多く、
「購入できるが権限が付かない」「復元できない」は実際に起きます。
**テスト期間中に必ず通してください。**

## 🔴 順番に罠があります

**Playのアプリ内商品は、Billingライブラリを含むAABを一度アップロード
するまで作成できません。**

一方 **RevenueCatの公開SDKキーはビルド時に埋め込む**必要があります
（`--dart-define-from-file=config/prod.json`）。

つまり、そのままだと堂々巡りになります。順番はこうです:

```
1. 今のAABを「内部テスト」にアップロード
        ↓                    ← これで商品作成が解禁される
2. Play / App Store で商品を作成（4つ）
     premium_monthly / premium_yearly
     ai_tickets_5 / ai_tickets_15
        ↓
3. RevenueCat でプロジェクト作成 → 商品を紐付け
        ↓
4. 公開SDKキー（iOS: appl_… / Android: goog_…）を取得
        ↓
5. config/prod.json に記入 → AAB を再ビルド
        ↓
6. クローズドテストへアップロード
```

> **1で「内部テスト」を使う理由**: クローズドテストの
> **14日カウントを消費しないため**です。

## もう一つの隠れた待ち時間

**RevenueCatがPlayのレシートを検証するには、Google Playのサービス
アカウントに権限を与える必要があります。反映に24〜48時間かかります。**

待ち時間なので、**商品を作る前に権限付与だけ先に出してください。**

## 商品IDは決め打ちしてあります

`config/dart_define.example.json` の既定値と一致させてください:

| 種別 | 商品ID |
|---|---|
| サブスク（月額） | `premium_monthly` |
| サブスク（年額） | `premium_yearly` |
| 消耗型 | `ai_tickets_5` |
| 消耗型 | `ai_tickets_15` |

違うIDで作った場合は `config/prod.json` 側を合わせれば動きます。

## 未設定のままテストするとどうなるか

**落ちません。** 「プランのご購入は現在準備中です」と表示されます
（8/18に修正済み）。**課金を後回しにしてテストを始めても問題ありません。**

ただし **A-8のチケット枚数表示は、課金が動くまで常に0枚**です。

# 3. 日程への落とし込み

| 日 | 広告 | 課金 |
|---|---|---|
| 8/19〜 | AdMob登録・**支払い情報** | **Playサービスアカウントの権限付与**（48h待ち） |
| 8/22 | — | 内部テストにAAB →**商品作成** |
| 8/23〜25 | — | RevenueCat設定 → キー取得 → 再ビルド |
| テスト期間 | **テストユニットのまま** | **ライセンステスター / Sandbox で購入を通す** |
| 公開直前 | **本番ユニットに差し替え**（私） | 金額の最終確認 |

# 4. 優先順位（率直に）

**9/1に間に合わせるなら、課金は「あると良い」、広告は「触らない」です。**

配信を止めているのは**プライバシーポリシーとアップロード鍵**であって、
広告でも課金でもありません。**そちらを先に片付けてください。**

課金は**テスト開始後に追加ビルドを配っても間に合います**
（クローズドテストは期間中いつでも新しいビルドを配れます）。
