## AIチケット購入者の除外（PM指摘・2026-08-12）

> サブスク登録せずにAIチケットの課金を行った際、購入分のチケットに
> 広告をかけたくない

**当初の実装では切り分けられていなかった。** `AdPolicy` は
プレミアム加入状態しか見ておらず、コード上も「`ai_tickets_*` は
広告表示に影響しない」と明記されていた（仕様書8.2の商品表に沿った設計）。
つまり**チケットで払ったAI相談でも広告が出る**状態だった。

**分離した**（`AiUsageStatus.nextSource` / `AdTriggerPolicy`）。

消費側が既に「どの財布から払うか」を決めていた:

1. サブスク加入 → 何も消費しない
2. **無料枠が残っている → 無料枠**
3. それ以外 → **チケット**

この判定を `AiUsageStatus.nextSource` に切り出し、
**消費側と広告側が同じ関数を見る**ようにした。ズレると
「チケットで払ったのに広告が出る」が復活し、**UI上は正常に見える**ため
気づけない。

| 支払い元 | 広告 |
|---|---|
| サブスク | 出ない |
| **無料枠** | **出る**（広告が支えているのはここ） |
| **チケット** | **出ない** |

**写真アップロードと証明書OCRはチケットの対象外**（PM判断 2026-08-12）。
チケットは商品名どおり「AI相談チケット」で、OCR はサーバ側の
10回/日 制限で保護している。**チケットを買っても写真とOCRの広告は消えない。**

**判定は消費の前に読むこと。** 消費後に読むと残高が動いているので、
最後の1枚を使った瞬間に広告が出る。

## 表示タイミング（PM承認済み）

| 種別 | タイミング |
|---|---|
| AI（#1〜#3） | **リクエストと並行**。送信してから広告を出し、閉じたときに回答が出ている |
| アップロード（#4〜#5） | **保存の永続化が完了した後**、画面を閉じる直前 |
| 証明書（#6） | 撮影＋OCRの完了後 |

### 不変条件：広告は意思表示と永続化の間に入れない

**保存より前に広告を出してはならない。** 広告中にアプリが落ちると記録が消える。
「保存完了 → 広告 → 画面を閉じる」の順なら、広告の時点で書き込みは
永続化済みなので、落ちても記録は残る。失われるのは広告の表示機会だけ。

AIも同じ理由で、リクエストは広告より先に投げる。送信前に広告を出すと、
送信が失敗したときに「広告だけ見せられて何も得られない」ことになる。

**この順序はテストで固定する**（下記テスト方針）。

### 検討：アップロードは利用者有利ではないか（PM指摘）

指摘の構図は正しい。保存が先に確定するので、広告中にアプリを終了すれば
記録だけ得て広告を回避できる。ただし実害は小さいと判断した。

- **インタースティシャルのインプレッションは「表示された時点」で計上される。**
  最後まで見る必要はなく、閉じても計上済み。回避するには「保存完了から
  広告が描画されるまでの一瞬」でアプリを落とす必要があり、毎回それを行うのは
  現実的な運用にならない
- **完了を強制する形式は「リワード広告」だが、本アプリには適さない。**
  リワード広告は「見れば報酬」という任意の取引であって、
  **自分の健康記録の保存を人質にする**のは筋が違う。
  中核機能をリワード広告で塞ぐのはAdMobのポリシー上も問題になりうる
- 逆順（広告→保存）にすれば強制できるが、**利用者のデータを失うリスク**を
  負う。広告1回の損失とは釣り合わない

結論として**現案を維持**する。運用データで回避が実際に多いと分かった場合は、
そのとき再検討する。

## 実装方針

### 1. 初期化と保持

- `main.dart` で `AdManager.initialize()`（`MobileAds.instance.initialize()`）
- `HomeShell` が `AdManager` を1つ保持し、`BillingRepository.premiumStatusChanges()`
  と接続。プレミアム状態が変わったら `AdPolicy` を差し替える
- サインイン直後とアクション画面を開いた時点で `preloadInterstitial()`

### 2. 表示ポイントを1箇所に集める

各画面に `maybeShowInterstitial()` を直接散らさない。散らすと
「どこで広告が出るのか」がコードを全部読まないと分からなくなる。

`AdTrigger` の列挙（`aiConsultation` / `aiReport` / `foodPortion` /
`healthRecordUpload` / `toiletRecordUpload` / `certificateCapture`）を作り、
画面はトリガー名だけを渡す。判定と表示は1箇所。

これで「広告が出る条件」がテストできる純粋な形になり、
一覧表がコードとして残る。

### 3. 頻度は1アクション単位（決定4）

時間間隔や1日の上限は**設けない**。健康記録の写真6枚は保存1回なので広告1回、
というのが決定の主旨。

> **リスクとして記録**: 1日に何度も記録を付ける利用者には、その回数だけ
> 広告が出る。AdMobのポリシー上も体験上も、運用データを見て
> 「N分に1回まで」等の上限が必要になる可能性がある。
> 実装は `AdTrigger` の判定に条件を1つ足すだけなので、後から入れられる。

### 4. アイコン・背景の除外

`pet_profile_form_screen.dart` の写真経路は他と混ざっていないので、
単にトリガーを呼ばないだけでよい。

### iOS の権限説明文（このプランと同時に対応・PM承認済み）

`ios/Runner/Info.plist` には usage description が**1つも無い**。iOSでは説明文
なしにカメラへアクセスした時点でアプリがクラッシュし、App Reviewも通らない。
広告の配線と同じタイミングで入れる。

| キー | 必要な理由 |
|---|---|
| `NSCameraUsageDescription` | `image_picker`（写真撮影） |
| `NSPhotoLibraryUsageDescription` | `image_picker`（ライブラリ選択） |
| `NSFaceIDUsageDescription` | `local_auth`（生体認証ゲート） |
| `NSUserTrackingUsageDescription` | `google_mobile_ads`（ATT） |

ATTの許可要求は**広告初期化の直前**に出す。起動直後に出すと拒否率が上がる。

## テスト方針

- プレミアム加入中はどのトリガーでも広告が出ない
- プレミアム状態が `unknown` の間は広告が出ない（確定するまで出さない）
- 未加入なら対象トリガーで出る
- **アイコン・背景の写真では出ない**
- 写真なしの健康記録・トイレ記録では出ない
- 健康記録に写真6枚でも**1回だけ**
- 証明書の撮影＋OCRで**1回だけ**
- 広告が未ロードでもアクション自体は完了する（広告待ちで止まらない）
- **保存は広告より先に完了する**（不変条件。順序が入れ替わると記録が失われる）

判定は純粋関数に切り出すので、いずれもウィジェットを立てずに書ける。

## 未解決・要注意

- **AdUnitIds はGoogleのテストIDのまま。** 実配信には PM の AdMob アカウントで
  発行した本番IDが必要（プラットフォーム別・プレースメント別）。
  **推測で本番IDを埋めないこと。**
  → クラウドフェーズの作業は `CLOUD_PHASE_TASKS.md` に集約した
- **`MobileAds.initialize()` は未呼び出し。** これが無いと広告は出ない
- **iOS の ATT（App Tracking Transparency）が未対応。** iOS配信では
  トラッキング許可のダイアログとその文言（`Info.plist` の
  `NSUserTrackingUsageDescription`）が必要になる可能性が高い。
  未許可でも広告自体は出せるが単価が下がる。**実機確認フェーズで要確認**
- **広告の実挙動は未検証。** エミュレータ／Web では確認できないため、
  実機確認フェーズまで動作は未確認のまま
- バナーは今回対象外（決定5）。`BannerAdWidget` は実装済みのまま残す
