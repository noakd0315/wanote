## 🔴 輸出コンプライアンス（要調査・実登録前に決着させること）

**PM判断: 2026-08-16、その場で答えず調査フェーズを設けることにした。**

TestFlight にビルドを配信するだけでも、`ITSAppUsesNonExemptEncryption`
（またはApp Store Connect上の同等の設問）への回答が要る。実登録では
避けて通れない。

### なぜ即答できないか

Apple の設問は、書類提出が必要な条件をこう書いている。

> 標準的な暗号化アルゴリズム（Appleのオペレーティングシステム内の暗号化を
> 使用したり、それにアクセスをしていないアルゴリズム）

このアプリの実態:

| | 判定 |
|---|---|
| 独自・非標準のアルゴリズム | **無し**（自前実装はゼロ） |
| `flutter_secure_storage` | iOSキーチェーンを使用 → 該当しない |
| HTTPS/TLS 全般 | 通信保護のみ |
| 🔴 **Firebase SDK（特に Firestore）** | **gRPC/BoringSSL を同梱**しており、Apple のネットワーク層をそのまま使っていない |

最後の1行が論点。**「標準アルゴリズムだが Apple OS の暗号化ではない実装」**
に文言上は当てはまり得る。Firebase を使うアプリの大半は免除として申告して
いるが、それは慣行であって、設問を厳密に読むと自明ではない。

### 決着させるべきこと

- [ ] 免除に該当するか（該当類型：「認証のためだけの使用」等）
- [ ] 該当するなら `ITSAppUsesNonExemptEncryption = false` を `Info.plist` へ
      （毎ビルドの質問が消え、CIがそのまま配信できる）
- [ ] 該当しないなら **CCATS または ERN の取得**。BIS への申請で**数週間**
- [ ] フランス市場に出すなら別途宣誓書

### 日程への影響

🔴 **書類が必要と判断した場合、取得に数週間かかる。** 9/30 の締切から逆算
すると、**Play の「12人×14日」と並ぶ律速になり得る。** 実登録の直前に着手
すると間に合わない。

**これは輸出規制の法的申告であり、PMの責任範囲。** 判断がつかない場合は
Apple のサポートか専門家に確認すること。

## iOSの権限ダイアログを英語化する（2026-08-18 記録）

`ios/Runner/Info.plist` の `NSCameraUsageDescription` /
`NSPhotoLibraryUsageDescription` / `NSFaceIDUsageDescription` が
日本語で固定されている。英語話者には日本語のダイアログが出る。

`CFBundleLocalizations` を宣言したので**OSが出すUI（カメラ・写真
ピッカー等）は端末の言語に追従する**ようになったが、これらの文面だけは
アプリ側の文字列なので追従しない。

必要な作業:
- `ios/Runner/ja.lproj/InfoPlist.strings` と `en.lproj/InfoPlist.strings` を追加
- **Xcodeプロジェクト（project.pbxproj）にリソースとして登録**する必要がある

pbxproj の編集を伴うため、iOSビルドを壊すと確認できるのが
Codemagic のビルド後になる。まとまった時間があるときに着手すること。

## AIレポートのPDF出力を削除した（2026-08-18・PM判断）

## Firebase の Web アプリ登録をいつ消すか（2026-08-18 記録）

Firebase プロジェクトに **Web アプリ**（`1:715210245467:web:...`）が登録されている。
開発中、Windows 上で `flutter run -d chrome` を使って画面を確認するために作った
もので、**配信物ではない**。

### 消してよいタイミング

**内部テストと審査が完全に終わってから。** それまでは残す。理由:

- `lib/firebase_options.dart` に `web` の設定が残っており、`kIsWeb` の分岐から
  参照される。消すと Web でのデバッグ実行ができなくなる
- 現在も画面確認の最速手段が Chrome 実行である（実機ビルドは数分かかる）

### 消すときにやること

1. Firebase コンソール → プロジェクトの設定 → 「マイアプリ」から Web アプリを削除
2. `flutterfire configure` を再実行して `firebase_options.dart` を再生成
   （`web` の項目が消える）
3. `kIsWeb` 分岐を持つコードの整理:
   - `lib/shared/config/auth_emulator_seed_web.dart`
   - `lib/shared/config/backend_config.dart`（ローカル開発用フォールバック）
   - `AdManager.platformSupported` / `ReminderNotificationAdapter.platformSupported`
4. `web/` ディレクトリの削除を検討（残しても配信物には含まれない）

### 消さなくても実害はあるか

**ストア配信・審査への影響はない。** Web アプリの登録は Firebase 内部の話で、
Play / App Store からは見えない。**急いで消す必要はない。**

ただし Firebase の Web API キーは `firebase_options.dart` 経由でアプリの
バイナリに含まれる。Web アプリを残す限り、そのキーも残る。
セキュリティは Firestore/Storage ルールで担保しているため問題にはならないが、
**使わないものは消しておく方が、後から見た人が迷わない。**

## リリース後のアップデート用テストデータ環境（2026-08-18・PM提起）

**PM 指摘: アップデートに向けたテストデータ環境が無いのはまずい。**
現状、開発中の動作確認は**本番 Firebase プロジェクト（`wanote-7dca0`）**の
データで行っている。公開後は、ここに**実利用者のデータが入る**。

### 何がまずいか

- **実利用者のデータを見ながら開発することになる。** 医療情報を扱うアプリで、
  プライバシーポリシーにも書いていない扱い方になる
- 検証のために作ったゴミデータが本番に混ざる
- 破壊的な検証（アカウント削除・データ移行）が本番でしかできない
- Firestore のルール変更やインデックス追加を、**本番で試すことになる**

### 選択肢

**案A: Firebase プロジェクトを分ける（推奨）**
`wanote-dev` を新規作成し、開発・検証はそちらへ向ける。
- `--dart-define-from-file=config/dev.json` で切り替える仕組みは既にある
- `firebase_options.dart` を環境ごとに持つ必要があり、`flutterfire configure`
  の運用を整理する必要がある
- Worker も dev 用に分ける（Cloudflare の環境またはワーカー名を分ける）
- **費用**: Firebase の無料枠内で収まる見込み

**案B: エミュレータを使う**
`firebase.json` にエミュレータ設定は既にある（Auth/Firestore/Storage）。
- 追加費用ゼロ、ネットワーク不要
- ただし **RevenueCat と AdMob と Anthropic は繋がらない**ので、
  課金・広告・AI の検証はできない

**現実的には A と B の併用。** 日常の画面確認は B、
課金や AI を含む通し確認は A。

### いつやるか

**公開前にやるのが理想だが、公開を遅らせてまでやるものではない。**
公開直後、実利用者がまだ少ないうちに着手するのが現実的。

**着手の判断材料**: 実利用者が1人でも入った時点で、本番での検証は
「他人のデータがある場所で作業する」ことになる。そこが分岐点。

## 現状

出している。

```
狂犬病ワクチン
ワクチン ・ 毎年
```

`次回予定日` は接種記録が持っていて、**プログラムを開かないと見られない**
（[prevention_program_list_screen.dart:157](../lib/features/medical/presentation/prevention/prevention_program_list_screen.dart:157)）。

実際に `狂犬病ワクチン` へ `実施日 2026-04-10 / 次回 2027-04-10` を

各行の subtitle を `ワクチン ・ 毎年 ・ 次回 2027/04/10` にする。

  `latest_certificates.dart` と同じ「種別ごとの最新だけ」を取る形を流用できる
- 記録が0件のプログラムは `次回` を出さない（初期の4件は記録なしで作られる）

# AI の回答が Markdown のまま表示される

登録: 2026-08-19（ストア用スクリーンショットの撮影中に発見）

## 症状

AI の回答が**記法のまま**画面に出る。実際に出た文字列:

```
# 食事配分についてのご質問ですね

体重4.8kgの成犬であれば、114g/日を**2〜3回に分けて与える**ことをお勧めします。

**配分例：**
- 2回食：朝57g、夜57g
```

`#` と `**` がそのまま読める状態で、**AI 機能全体に影響する**。

## 原因

回答を素の `Text` / `SelectableText` に流しているだけで、整形も除去もしていない。

| 画面 | 箇所 |
|---|---|
| 給餌アドバイス | `lib/features/ai/presentation/food_portion_screen.dart:555` |
| AI相談 | `lib/features/ai/presentation/consultation_screen.dart:357` |

プロンプト側にも「Markdown を使うな」の指示がない（`functions/src` を確認済み。
`ocrParsing.ts` だけが `no markdown fences` と書いているが、これは JSON 用）。

## 対応案

| 案 | 内容 | 評価 |
|---|---|---|
| A | プロンプトに「plain text で答える」を追加 | 安いが、モデルは時々破る。**単独では不十分** |
| B | 表示直前に記法を落とす（`**` を外す、`#` を見出しに、`-` を `・`）。依存追加なし | **すぐ効く。まずこれ** |
| C | Markdown として描画する | 本筋。ただし `flutter_markdown` は 2025 に開発終了しており、
代替パッケージの選定が要る |

**推奨は A＋B を先に入れ、C は後日。** 公開前に A＋B だけでも入れる価値がある
（AI はこのアプリの差別化点で、いま一番みすぼらしく見える箇所）。
