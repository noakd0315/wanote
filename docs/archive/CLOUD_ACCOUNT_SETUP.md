## ステップ0：先に決めるもの（アカウント登録前）

**ここが決まらないと後戻りできない。** バンドルIDは App Store Connect と
Play Console では**アプリ作成後に変更できない**。

- [x] **0-1 バンドルID / applicationId** → **`jp.wanote.app` に決定**（2026-08-11）
      ドメイン `wanote.jp` を取得済み（サーバーは未契約）。
      逆順に戻すと `app.wanote.jp` で、所有ドメインのサブドメインと整合する。
      **コード側は未変更**（現在も `com.example.wanote`）。
      次回セッションの最優先タスク。手順は `SESSION_HANDOVER.md` 0-D を参照
- [ ] **0-2 アプリ表示名**
      現在 iOS は `Wanote`、Android は `wanote` で**不一致**。どちらかに揃える
- [~] **0-3 サポート用メールアドレス** → **`support@wanote.jp`**、
      **Cloudflare Email Routing で受信**（無料）と決定（2026-08-11）。
      送信は当面できない（返信は個人アドレスから出る）。
      必要になったら Google Workspace 等へ移す。**MXを差し替えるだけで
      アドレスは変わらない**ので、ストア登録済みでも後から移行できる

      **重要**: Apple / Play の**アカウント登録用アドレスには使わない**。
      DNS や転送が壊れると復旧メールを受け取れなくなる。
      登録は既存の安定したアドレスで行い、`support@wanote.jp` は
      **公開窓口専用**にする
- [ ] **0-4 プライバシーポリシーのURL**
      **App Store・Play・AdMob の3つすべてで必須**。公開URLが要る。
      本アプリはペットの医療情報とAI送信を扱うので、
      「何を集め」「どこへ送り」「誰が見られるか」を明記する必要がある
- [x] **0-5 開発者名義** → **個人で配信**（2026-08-12 PM判断）。
      状況次第で法人化、または法人への帰属を検討する

      **スケジュールへの影響（重要）**: Play Console は個人アカウントの場合、
      新規アプリに**「12人のテスターが14日間継続テスト」**の要件がある
      （2023年以降）。**14日は最短でも動かせない**ので、
      9/30 の締切から逆算すると **9月中旬までにクローズドテストを開始**し、
      **テスターを12人確保**しておく必要がある。
      → `CLOUD_PHASE_TASKS.md` H-1 に記録

      **後から法人へ移す場合**:
      - Apple: App の**移管（App Transfer）**が可能。ただし条件があり、
        **未解決の契約や一部の機能があると移管できない**
      - Play: **アプリの移行**が可能だが手続きに時間がかかる
      - **RevenueCat / AdMob / Firebase も移管または再作成**が必要
      - **プライバシーポリシーの【事業者名】も書き換えになる**
      → 個人で出しておいて後で移す判断自体は妥当。
        ただし**リリース後の移管は手数がかかる**ことは織り込むこと

## 取得済みドメインの使い道（2026-08-11 決定）

`wanote.jp` を取得済み。サーバーは契約していないが、**Cloudflare のアカウントは
Workers 用にどのみち作る**ので、それだけで足りる。

| サブドメイン | 用途 | 手段 |
|---|---|---|
| `wanote.jp` | LP・**プライバシーポリシー** | Cloudflare Pages（無料） |
| `api.wanote.jp` | Workers バックエンド | Workers のカスタムドメイン |

### `api.wanote.jp` を挟む理由（重要）

`AI_BACKEND_BASE_URL` は **`--dart-define` でビルド時に埋め込まれる定数**。
`*.workers.dev` を直接埋めて配信すると、**出荷済みアプリではURLを変更できない**。
Cloudflareのアカウント名やWorker名を変えたくなった時点で詰む。

自前ドメインを挟んでおけば裏側をいつでも差し替えられる。追加費用なし。

プライバシーポリシーのURLは App Store・Play・AdMob の**3つすべてで必須**なので、
置き場はどのみち要る。

## Cloudflare でまとめて片付く作業（先にやると効率が良い）

DNS を Cloudflare に移すと、以下が**すべて無料**で1箇所に集まる。
Apple / Play の審査を待つ間に進められる。

1. **DNS を Cloudflare に移管**（ネームサーバをレジストラ側で変更）
2. **Email Routing** — `support@wanote.jp` → 手持ちのGmail等へ転送。
   MXレコードは自動設定される
3. **SPF / DMARC を設定** — `wanote.jp` からメールを送らないなら、
   厳格な設定で**第三者によるなりすまし送信を防げる**。
   ドメインを持っているだけの状態は、騙られうる状態でもある
4. **Pages** — `wanote.jp` に**プライバシーポリシー**とLPを公開（0-4）
5. **Workers のカスタムドメイン** — `api.wanote.jp`

## お知らせの出し方（実装済み・2026-08-12）

管理画面は作っていません。**Firebase コンソールで1件書けば出ます。**

Firestore → `announcements` コレクション → ドキュメントを追加:

| フィールド | 型 | 必須 | 内容 |
|---|---|---|---|
| `title_ja` | string | ● | 見出し |
| `body_ja` | string | ● | 本文 |
| `title_en` / `body_en` | string | | 英語。無ければ日本語で表示 |
| `published_at` | timestamp | | この時刻から表示。未来にすると予約投稿になる |
| `expires_at` | timestamp | | **この時刻で自動的に消える** |
| `important` | boolean | | true にすると**サインイン画面にも**出る（障害時用） |

**`expires_at` は必ず入れてください。** 「8/13〜8/20 は問い合わせ対応を
お休みします」を消し忘れると、営業しているのに休業中と表示され続けます。

**`important` はサインインできない障害のときだけ**にしてください。
サインイン画面に常時何か出ている状態は、初回利用者の離脱要因になります。

削除するときはドキュメントごと消せば消えます。

## ステップ1：先に着手すべきアカウント（審査待ちが発生する）

**この2つは承認までに日数がかかる。他より先に申請すること。**

- [ ] **1-1 Apple Developer Program**
      - 用途：iOS配信、Sign in with Apple、App Store Connect、ATT
      - 費用：**年額 99 USD**（記事執筆時点。要確認）
      - 前提：Apple ID、2ファクタ認証、支払い手段。
        **法人名義は D-U-N-S番号が必要**で、取得に日数がかかる
      - 審査：個人で数日、法人はさらにかかる
      - **これが無いと iOS 側は何も進まない**（Sign in with Apple も含む）

- [ ] **1-2 Google Play Console**
      - 用途：Android配信
      - 費用：**登録料 25 USD（買い切り）**（記事執筆時点。要確認）
      - 前提：Googleアカウント、支払い手段、**本人確認書類**
      - 審査：本人確認に数日かかることがある
      - 注意：0-5 の個人/法人の判断がここに効く

## ステップ2：すぐ作れるアカウント（審査なし）

- [ ] **2-1 Google アカウント**（プロジェクト用に分けることを推奨）
      Firebase・AdMob・Play Console の土台になる。
      個人アカウントと混ぜると後で権限移譲が面倒になる

- [ ] **2-2 Firebase**（無料で開始可）
      - 用途：認証・Firestore・Storage・プッシュ通知
      - 前提：Googleアカウント
      - 注意：Firebaseプロジェクトを作ると **Google Cloud プロジェクトが同時に
        できる**。Worker用のサービスアカウントはそちら側で発行する
      - 課金：Blazeプラン（従量課金）への切替が必要になる可能性がある。
        無料枠の範囲なら実質0円だが、**カード登録が必要**

- [ ] **2-3 Cloudflare**（無料で開始可）
      - 用途：Workers（バックエンド）
      - 注意：**Durable Objects を使っている**。SQLiteベースのDurable Objectは
        無料プランでも使える想定で `wrangler.toml` を書いてあるが
        （`new_sqlite_classes`）、**プラン条件は変わりうるので要確認**。
        有料が必要なら Workers Paid は月額5USD程度（要確認）

- [ ] **2-4 Anthropic Console**
      - 用途：Claude API（AI相談・レポート・OCR）
      - 前提：**支払い手段の登録が必要**
      - 注意：APIキーは Worker のシークレットにのみ設定する。
        **クライアントには絶対に置かない**（現状もそうなっている）

- [ ] **2-5 AdMob**
      - 用途：広告
      - 前提：Googleアカウント。**支払い・税務情報の登録**が要る（収益受取のため）
      - 注意：アプリ登録には**バンドルID**が要る（ステップ0）。
        ストア公開前でも登録は可能

## ステップ2.5：iOSビルド環境（2026-08-11 決定）

**Mac は用意せず、Codemagic（クラウドCI）でビルドする。**

- [ ] **2-6 Codemagic**
      - 用途：iOS のビルドと App Store Connect への配信。
        `flutter build ipa` は Xcode を要するため **Windows では実行できない**。
        クラウド上の Mac に任せる
      - 費用：無料枠あり（**条件は要確認**）
      - 前提：**Apple Developer Program が必要**（1-1）。
        App Store Connect の API キーを渡すと、
        **証明書・プロビジョニングプロファイルを自動管理**してくれる。
        Mac なし運用で最も厄介な署名まわりをここに任せられるのが採用理由
      - 実機確認は **TestFlight** 経由（CIがビルド→アップロード→iPhoneで受け取る）

> Flutter アプリは動かせない。使うには全面書き直し（Dart 約20,000行・
> テスト227件）が必要になり、現実的でない。

## 私（開発側）が代わりにできること・できないこと

**できない**

- アカウントの作成、認証情報の入力、支払い手段の登録
  → **これらは PM ご本人が行う必要がある**。パスワードやAPIキーを
    こちらに共有する必要もない

**できる**

- **バンドルIDの一括変更**（0-1 が決まり次第。Android/iOS 両方）
- アプリ表示名の統一（0-2）
- 発行された値をコード／設定に反映する作業
  （`firebase_options.dart`、`AdUnitIds`、`EntitlementIds` など）
- `wrangler secret put` で設定すべき値の一覧提示（`CLOUD_PHASE_TASKS.md` B-1）
- プライバシーポリシーに書くべき項目の洗い出し
  （実装から見て、実際に何を収集・送信しているか）
