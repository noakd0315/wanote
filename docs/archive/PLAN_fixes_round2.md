## 依存関係のある2組

### 組1: トイレ記録の写真（要望1 × バグ2）

- **バグ**: 排便の記録は写真を追加しても**詳細を確認できない**
- **要望**: 写真を添付したら**「日々の記録」として登録**できないか
  （PM注: 「一覧表示しなくても問題がなくなる」）

**要望を実装すると、バグは直す必要がなくなります。** 写真は健康記録の
詳細画面で見られ、その画面は**すでに存在して動いています。**

**ただし設計判断が要ります。** 写真をどちらが持つのか:

| 案 | 内容 | 懸念 |
|---|---|---|
| **A** | トイレ記録を保存し、**同じ写真で健康記録も作る** | **2件になる。**片方を消してももう片方が残る |
| **B** | 写真付きの排便は**健康記録としてのみ**保存し、トイレ記録には写真を持たせない | **トイレの回数統計から漏れる** |
| **C** | トイレ一覧に**詳細画面を足すだけ**（要望は見送り） | 記録が増えない。要望は満たさない |

> **AとBは、どちらも「記録が1つか2つか」という数え方の問題**になります。
> トイレの回数はグラフと異常検知の入力なので、**Bは検知精度に影響します。**

### 組2: 予防医療と投薬（要望2）

- **要望**: フィラリア・ノミダニは**投薬**なので、**投薬履歴にも出したい**。
  証明書として扱うか投薬として扱うか**選べると良い**

現状は**別々の入れ物**です。

| | 保存先 | 持っているもの |
|---|---|---|
| 投薬 | `medications` | 薬名・用量・期間・リマインダー |
| 予防医療 | `prevention_records` | 接種日・次回予定・**証明書画像**・OCR |

| 案 | 内容 | 懸念 |
|---|---|---|
| **A** | 予防医療の記録に「投薬として扱う」印を付け、**投薬履歴の画面が両方を読んで表示** | データは1か所のまま。**表示側だけの変更で済む** |
| **B** | 予防医療を保存したとき、**投薬レコードも作る** | 2件になる。削除・編集の整合が必要 |
| **C** | 見送り | |

> **Aを推奨します。** 実体を増やさずに済み、削除の整合も崩れません。
> リマインダーは投薬側の仕組みなので、**予防医療にも通知が要るなら
> 追加の設計**になります（現状は予防医療にもリマインダーがあります）。

## 独立している項目

### バグ3: AI相談の入力と回答が残る／履歴が再表示できない

**回答は保存されています**（`aiResponse`）。**履歴を開けないだけ**です。

- **クリアボタン**を追加（入力欄と回答を消す）
- **履歴をタップすると、質問と回答を再表示**

> PM: 「回答が見れないのであれば履歴として残す必要はない」
> → **見られるようにすれば残す価値があります。** 消す必要はありません。

### バグ4: 写真6枚でのメモリ異常終了

**保存時は既に1280pxへ圧縮しています。** 問題は**その手前**です。

`image_picker` に上限を渡していないため、**撮影直後に原寸のまま読み込みます。**
最近のスマホは1枚あたり数千万画素あり、**6枚を同時に抱えると落ちます。**

- `image_picker` に **maxWidth/maxHeight/imageQuality** を渡し、
  **OSに縮小させてから受け取る**
- 副次効果として**アップロードが速くなり、広告までの待ちも短くなります**

### 要望3: 給餌量に現在の分量を入力

**現状は計算値を渡すだけ**なので、PM指摘のとおり**固定回答に見えます。**
「いま与えている量」を任意入力にして、**計算値との差**を助言できるようにします。

## 進め方の提案

**依存のない4件を先に片付け、組1・組2は判断をもらってから着手します。**

```
1. 画像の縮小        （バグ4。メモリと待ち時間の両方に効く）
2. AI相談のクリア    （バグ3の前半）
3. AI相談の履歴表示  （バグ3の後半）
4. 給餌量の入力      （要望3）
        ↓ 判断待ち
5. 組1（トイレ写真） A / B / C
6. 組2（予防と投薬） A / B / C
```
