# ⚠️ 絶対に間違えてはいけないもの

アプリは**下の文字列をそのまま探しに行きます。** 1文字でも違うと、
「購入ボタンが出ない」「購入しても機能が解放されない」という形で失敗します。
**エラーはどこにも出ません。** コピー＆ペーストしてください。

| 何の値か | 入力する文字列 |
|---|---|
| 商品ID（月額サブスク） | `premium_monthly` |
| 商品ID（年額サブスク） | `premium_yearly` |
| 商品ID（AIチケット5回） | `ai_tickets_5` |
| 商品ID（AIチケット15回） | `ai_tickets_15` |
| Entitlement（権利）の識別子 | `premium` |

## 用語（3つだけ）

| 用語 | 意味 | wanote での例 |
|---|---|---|
| **Product（商品）** | ストアで売る品物そのもの | 月額プラン、チケット5回 |
| **Entitlement（権利）** | 「買うと何ができるか」のラベル | `premium`（広告なし＋AI無制限） |
| **Offering（売り場）** | アプリに表示する商品の並び | プラン画面に出る4つ |

月額を買っても年額を買っても「プレミアムが使える」のは同じです。
その「同じ」をまとめるのが Entitlement です。アプリは商品名ではなく
**`premium` を持っているかどうか**だけを見ています。

# 第0部　AABを内部テストへ上げる

## なぜ最初にこれが必要か

**Play Console は、Play Billing ライブラリを含むビルドがトラックに
アップロードされるまで、商品を作らせません。** パッケージ名を実際の
アップロードで確認するまで、商品作成の画面が使えない仕組みです。

**このAABに RevenueCat の設定は一切含まれません。**
商品は Play Console 側に作るものなので、いま手元にあるビルドで構いません。
（現ビルドに `com.android.vending.BILLING` が含まれていることは確認済みです）

## 0-1. アップロード鍵を作る（PM作業）

PowerShell で以下を**そのまま**実行します。

```powershell
keytool -genkey -v -keystore C:\Users\tomoc\wanote-upload.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload -dname "CN=wanote, O=wanote, C=JP"
```

聞かれるのは**パスワードだけ**です。

| # | 画面に出る文言 | 入れるもの |
|---|---|---|
| 1 | キーストアのパスワードを入力してください | 任意のパスワード。**必ず記録** |
| 2 | 新規パスワードを再入力してください | **1と同じものをもう一度** |

最後に次が出たら、**そのままEnter**で完了です。

```
<upload>の鍵パスワードを入力してください
        (キーストアのパスワードと同じ場合はRETURNを押してください):
```

> **なぜ `-dname` を付けるのか**
>
> これを付けないと、姓名・組織・国コードを1つずつ聞かれ、最後に
> 「…でよろしいですか」と確認されます。**この確認が日本語環境では通りません。**
>
> keytool は入力を「表示言語に合わせた肯定語」と比較します。日本語環境では
> `はい` だけが一致し、`yes` も `y` も「いいえ」扱いです。ところが
> PowerShell から日本語を打つと、コンソールの文字コードと Java が読む
> 文字コードが食い違い、**`はい` と打っても一致しません**。
> 結果、何を入れても最初の質問に戻り続けます（PM報告, 2026-08-18）。
>
> `-dname` は、その質問と確認をまとめて省略します。聞かれるのは
> パスワードだけになり、パスワードは半角なので化けません。
>
> `CN=wanote, O=wanote, C=JP` の中身は証明書に記録されるだけで、
> **利用者には表示されません**。Google Play は最終的に Google 自身の鍵で
> 署名し直すため、ストア上の表示にも影響しません。

> **すでに何度か失敗して終了している場合、鍵はまだ作られていません。**
> 上のコマンドで作り直してください。途中まで作られたファイルが残っていたら、
> `del C:\Users\tomoc\wanote-upload.jks` で消してから実行します。

## 0-1b. できたか確認する

```powershell
keytool -list -v -keystore C:\Users\tomoc\wanote-upload.jks -alias upload
```

パスワードを入れて、`別名: upload` と有効期限が表示されれば成功です。

> 🔴 **この .jks とパスワードを失うと、二度とアプリを更新できません。**
> クラウドストレージなど、PCが壊れても残る場所にバックアップしてください。
> Google Play アプリ署名を使うので復旧手段はありますが、手続きは面倒です。

## 0-2. パスワードをアプリのビルド設定に渡す（PM作業）

`C:\Dev\wanote\android\key.properties` を**新規作成**し、以下を書きます。

```properties
storeFile=C:\\Users\\tomoc\\wanote-upload.jks
storePassword=（0-1で決めたパスワード）
keyAlias=upload
keyPassword=（0-1で決めたパスワード。同じで構いません）
```

> - **バックスラッシュは2つ重ねます**（`\\`）。1つだとパスとして読めません
> - このファイルは Git に入りません（`.gitignore` 済み）
> - 🔒 **パスワードは私に送らないでください。** このファイルに書くだけで、
>   ビルドは通ります

## G-3. サービスアカウントを作る（最優先）

RevenueCat が Google に「この購入は本物か」を問い合わせるための、
**専用の入館証**を作ります。3段階あります。

### G-3-A. API を2つ有効にする【Google Cloud】

1. https://console.cloud.google.com を開く
2. **画面上部のプロジェクト名をクリック**して、プロジェクトを選ぶ
   - Firebase で使っている `wanote-7dca0` が一覧にあるはずです。それを選びます
   - > **どのプロジェクトでも構いません**が、後で分からなくならないよう
   >   wanote 用のものを選んでください
3. **上部中央の検索窓**に `Google Play Android Developer API` と入力
4. 検索結果の同名の項目をクリック
5. 青い **「有効にする」** ボタンを押す
   - すでに「管理」と表示されていれば、有効化済みです。次へ進みます
6. **もう一度検索窓**に `Google Play Developer Reporting API` と入力
7. 同じように **「有効にする」**

> **なぜ2つ必要か**: 前者が購入内容の確認、後者が売上レポートの取得に
> 使われます。片方だけだと RevenueCat 側でエラーになります。

### G-3-B. サービスアカウントと鍵を作る【Google Cloud】

1. 左上の **ハンバーガーメニュー（≡）** をクリック
2. **「IAM と管理」** にマウスを乗せる → **「サービス アカウント」** をクリック
3. 上部の **「＋ サービス アカウントを作成」** をクリック
4. **ステップ1「サービス アカウントの詳細」**
   - サービス アカウント名: `revenuecat`
   - サービス アカウント ID: 自動で入ります。そのままで構いません
   - 説明: 空欄で構いません
   - **「作成して続行」** をクリック
5. **ステップ2「このサービス アカウントにプロジェクトへのアクセスを許可する」**
   - **何も選ばずに「続行」** をクリック
   - > ロールは不要です。権限は Google Cloud ではなく、
   >   次の G-3-C で Play Console 側から与えます
6. **ステップ3「ユーザーにこのサービス アカウントへのアクセスを許可」**
   - 何も入力せずに **「完了」**
7. 一覧に `revenuecat@...` の行ができます。**メールアドレスをコピー**して
   メモしてください（`revenuecat@wanote-7dca0.iam.gserviceaccount.com` の形）
8. その行の**右端の「⋮」（点3つ）** → **「鍵を管理」**
9. **「鍵を追加」** → **「新しい鍵を作成」**
10. **「JSON」** が選ばれていることを確認して **「作成」**
11. JSON ファイルが**自動でダウンロード**されます
    - > 🔒 **これは秘密の鍵です。** `C:\Users\tomoc\keys\` など、
    >   リポジトリの外に移動して保管してください。
    >   **再ダウンロードはできません**（無くしたら作り直しになります）

### G-3-C. Play Console 側で権限を与える【Play Console】

**ここを忘れると、鍵はあっても何もできません。**

1. https://play.google.com/console を開く
2. **左メニュー最下部の「ユーザーと権限」**
   - > アプリの中ではなく、**アカウント全体のメニュー**です。
   >   アプリを開いている場合は、左上の「すべてのアプリ」で一度戻ります
3. 右上の **「新しいユーザーを招待」**
4. **メールアドレス**の欄に、G-3-B-7 でコピーしたアドレスを貼り付け
5. **「アプリの権限」** タブ → **「アプリを追加」** → **wanote** を選択
6. 権限の一覧で、以下の**3つ**にチェック

   | チェックする権限 | 備考 |
   |---|---|
   | **アプリ情報の閲覧、一括レポートのダウンロード（読み取り専用）** | |
   | **売上データ、注文、解約アンケートの回答の閲覧** | 旧称「財務データ、注文、定期購入のキャンセル アンケート回答の閲覧」 |
   | **注文と定期購入の管理** | |

   > **「アプリの品質情報の閲覧」は別物です。** あちらは Android vitals
   > （クラッシュ統計）用で、課金とは関係ありません。
   >
   > **Google は権限名をよく変えます**（2026-08-18 時点で上記の表記に
   > 変わっていました）。名前が違っても、
   > 「アプリ情報の閲覧」「売上・財務データの閲覧」「注文と定期購入の管理」
   > の3つの役割に当たるものを選べば通ります。
   >
   > これらは **「アプリの権限」ではなく「アカウントの権限」タブ**にある
   > 場合があります。タブが2つあれば両方確認してください。
7. **「適用」** → **「変更を保存」** → 右下の **「ユーザーを招待」**
   - > 保存を押さずに閉じると、権限が付きません

> ⏳ **ここから最大36時間。** この間、RevenueCat 側で
> 「Invalid Play Store credentials」と出ますが**故障ではありません**。
> 先に進んで構いません。

## G-2. アプリ内アイテムを2つ作る【Play Console】

定期購入と違って**1階層**です。ただし **アイコンが必須** で、これが無いと

### 用意するもの（先に）

|---|---|

規定は **512×512 ピクセル / 32ビット PNG / 1MB以下**。用意済みのものは
各8KB程度で収まっています。

### 手順（1つ目）

1. 左メニュー **「収益化」** → **「アプリ内アイテム」**
2. **「アイテムを作成」**
3. **アイテム ID**: `ai_tickets_5`

   >   使えるのは数字・英小文字・アンダースコア・ピリオドだけです
4. **タイトル**: `AI相談チケット 5回分`
   - 上限は全角27文字ですが、**全角12文字以内が推奨**です。
   >   購入シートでは途中で切られることがあります
5. **説明**: `AI相談を5回ご利用いただけます。`
   - 上限は全角100文字
6. **アイコン**: 上で用意した `ai_tickets_5.png` をアップロード
7. **購入オプション ID**: `buy`
   - > 定期購入の「基本プラン」に相当する階層です。Play の購入オプションは
   >   **購入（買い切り）とレンタルの2種類**なので、`buy` にしておくと
   >   将来レンタルを足したときにも読んで分かります
   - > ⚠️ **「下位互換性あり」（backwards compatible）を必ず有効にしてください。**
   >   理由は下の「🔴 ここを間違えると動きません」を参照
8. **購入オプションのタイプ**: **購入（買い切り）**（レンタルではない）
9. **価格**: 日本 **¥300** / アメリカ **$2.99**（`docs/PRICING.md` が正）
10. **複数数量**・**Play Points 限定**: どちらも**触らなくて構いません**
11. **「保存」**
12. 一覧に戻り、その行を **「有効化」**

### 🔴 ここを間違えると動きません

**アプリは商品IDを完全一致で判定しています。**

```dart
// lib/features/billing/domain/purchase_event_handler.dart
switch (productId) {
  case AppConfig.aiTickets5ProductId:   // 既定値 'ai_tickets_5'
```

購入オプションが増えたことで、識別子が `ai_tickets_5:buy` の形になる
可能性があります。**そうなるとこの switch が一致せず、購入してもチケットが
付与されません。**

**対策は2段構えです。**

1. **購入オプションを「下位互換性あり」にする。**
   これが有効なら、従来どおり `ai_tickets_5` だけで購入でき、RevenueCat も
   自動で取り込みます。無効だと手動インポートが必要になります
2. **それでも識別子に `:buy` が付く場合**は、RevenueCat のダッシュボードで
   実際の識別子を確認し、ビルド時に上書きします。**コード修正は不要です**

   ```
   --dart-define=PRODUCT_AI_TICKETS_5=ai_tickets_5:buy
   --dart-define=PRODUCT_AI_TICKETS_15=ai_tickets_15:buy
   ```

   （`config/prod.json` に書く形でも構いません）

**RevenueCat に取り込んだ直後に、表示されている識別子を必ず確認してください。**
定期購入は `premium_monthly:monthly` の形になることが分かっていますが、
アプリ内アイテム側は公式ドキュメントに明記がなく、実物を見るまで確定しません。

## A-1. サブスクリプションを2つ作る

### 先に知っておくこと（2026-08-20 に実画面で確認）

**「保存」ボタンはありません。入力すると自動保存されます。**
押せるボタンは **「審査用に追加」** だけですが、**これは今は押さないでください**
（理由は下記）。

**表示名は30文字、説明は45文字が上限**です。日本語も1文字は1文字として
数えます。超えると受け付けられません。

### 手順

1. **マイApp** → **wanote**
2. 左メニュー **収益化** → **サブスクリプション**
3. **サブスクリプショングループ** の「＋」
   - グループ参照名: `Premium`（内部用。ユーザーには見えません）
   - ※ Apple はサブスクを必ずグループに入れる決まりです。
     同じグループ内なら月額↔年額の乗り換えが自動処理されます
   - > **グループ自体にも表示名（ローカリゼーション）が要ります。**
   >   個々の商品とは別枠です。ここが空だと後で詰まります
4. グループを開き、**サブスクリプション**の「＋」
   - 参照名: `プレミアム月額`（内部用）
   - **製品ID: `premium_monthly`**
5. 作成後、その商品の画面で以下を埋めます。**それぞれ別の項目**で、
   ひとつでも欠けると `Missing Metadata` のままになります
   - **サブスクリプションの期間**: 1か月
   - **サブスクリプション価格**: 日本 **¥480** / アメリカ **$4.99**
   - **販売地域**: 日本・アメリカ
   - **App Store 情報（ローカリゼーション）**: 下表のとおり
6. 同じグループに2つ目。参照名 `プレミアム年額` /
   **製品ID `premium_yearly`** / 期間 **1年** /
   価格 日本 **¥4,800** / アメリカ **$39.99**

### 登録する文字列

**英語も登録してください。** 規定は「最低1言語」ですが、米国でも販売する
以上、英語を入れないと**米国のユーザーに日本語の表示名が出ます**。

**premium_monthly**

| | 日本語 | English |
|---|---|---|
| 表示名 | `wanote プレミアム（月額）` | `wanote Premium (Monthly)` |
| 説明 | `広告非表示・AI相談が使い放題になります` | `No ads and unlimited AI consultations` |

**premium_yearly**

| | 日本語 | English |
|---|---|---|
| 表示名 | `wanote プレミアム（年額）` | `wanote Premium (Yearly)` |
| 説明 | `広告非表示・AI相談が使い放題。年払いでお得` | `No ads and unlimited AI. Best value yearly` |

### ⚠️ 説明文に割引率（%）を書かないこと

**説明は言語ごと、価格はストアフロント（国）ごと**で、両者は一致しません。
数字を書くと必ずどこかで嘘になります。

| | 月額×12 | 年額 | 実際の割引 |
|---|---|---|---|
| 日本 | ¥5,760 | ¥4,800 | **16.7%（2か月分）** |
| 米国 | $59.88 | $39.99 | **33.2%（4か月分）** |

たとえば英語の説明に「33% off」と書くと、**日本のストアで英語表示にしている
利用者**には 16.7% しか割引がないのに 33% と表示されます。逆も同じです。

**割引率は書かず、「年払いでお得」のように率を含まない表現にしてください。**
実際の金額は購入画面に出るので、利用者が損をすることはありません。

### 「審査用に追加」を今は押さない

**押さなくても、必要なことは全部できます。**

| やりたいこと | 必要な状態 |
|---|---|
| RevenueCat に商品を取り込む | 保存されていれば足りる |
| **TestFlight / Sandbox で購入テスト** | **審査不要。`Ready to Submit` で購入できる** |
| 一般公開して実際に販売する | 審査の承認が必要 |

**最初のサブスクリプションは、アプリ本体のバージョンと一緒に審査へ出します。**
本体の申請準備ができるまで押しても進みません。

さらに、**審査用スクリーンショットが必須**（画面上は任意に見えます）で、
**一度アップロードすると削除できません**（差し替えのみ可）。RevenueCat 未設定の
うちにプラン画面を撮っても、商品が並んでいない空の画面になります。

**正しい順序**

```
1. 商品を保存だけしておく（自動保存）
2. RevenueCat を設定し、プラン画面に商品が並ぶ状態にする
3. その画面を撮って、審査用スクリーンショットとして登録する
4. アプリ本体の申請時に「審査用に追加」を押す
```

**プロモーション画像（1024×1024）は不要です。** App Store 上で App内課金を
宣伝したり、オファーコードを配ったりする場合にだけ必要になります。

   > 任意の名前で構いません。**パッケージ名はアプリの判定に使っていません。**
