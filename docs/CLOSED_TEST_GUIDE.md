# クローズドテストの進め方（Android / iOS）

作成: 2026-08-14

**結論から2つ:**

1. **iOS も同様にテストできます**（TestFlight）。むしろ **Play のような
   「12人×14日」の縛りはありません**
2. ただし **iOS は Mac が無いため Codemagic の設定が要る**ので、
   Android より準備が長くなります

# 申請の流れ（記録用・実機確認のあとで着手）

**前提: 実機確認が先です。** 実機で動かないものをテスターに配っても
意味がなく、クローズドテストの14日を無駄に消費します。

## 順番

```
0. 実機確認（← いまここ）
        ↓
1. ストア登録        Play $25 / Apple 年$99   ※本人確認に数日
        ↓
2. 公開準備物をそろえる
   - アップロード鍵（Android）
   - プライバシーポリシーを公開（両方に必須）
   - 事業者名の決定
   - ストア掲載文・スクリーンショット
   - データセーフティ／App のプライバシー申告
        ↓
3. Android: AAB を作成 → クローズドテスト開始
   iOS: Codemagic 構築 → TestFlight
        ↓
4. 🔴 Android のみ: 12人 × 14日間（短縮不可）
        ↓
5. 製品版アクセスを申請 → 審査 → 公開
```

## 日程で効いてくるもの

| | 待ち時間 | 短縮 |
|---|---|---|
| Play の本人確認 | 数日 | 不可 |
| Apple Developer の審査 | 数日 | 不可 |
| **Android の 12人×14日** | **14日** | **不可** |
| 製品版アクセスの審査 | 数日〜 | 不可 |
| アプリ審査（両ストア） | 数日 | 不可 |

**9/30 締切なら、9月上旬にはクローズドテストを開始したい**計算です。
**申請だけは早く出しておく**と、待ち時間が実装期間と重なって無駄がありません。

# 先に：Android で今すぐ詰まる箇所

## 🔴 リリース署名が未設定です

`android/app/build.gradle.kts` は現在こうなっています:

```kotlin
release {
    // TODO: Add your own signing config for the release build.
    // Signing with the debug keys for now, so `flutter run --release` works.
    signingConfig = signingConfigs.getByName("debug")
}
```

**デバッグ用の鍵で署名されています。Play はこれを受け付けません。**

### 必要な作業

**アップロード鍵（keystore）の作成が必要です。** PowerShell で:

```bash
keytool -genkey -v -keystore C:\Users\tomoc\wanote-upload.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

聞かれる内容:

| | |
|---|---|
| パスワード | 任意。**必ず控えてください** |
| 姓名・組織・都市など | 適当で構いません（**ストアには表示されません**） |

> 🔴 **この .jks ファイルとパスワードを失うと、二度とアプリを更新できません。**
> （Play App Signing の鍵アップグレード申請という救済はありますが、手間です）
>
> - **`C:\Dev\wanote` の中には置かない**（コミット事故防止）
> - **別の場所にバックアップ**（クラウドストレージ等）
> - パスワードはパスワードマネージャーへ

> **私に渡す必要はありません。** gradle 側の配線はこちらでやり、
> パスワードは `key.properties`（gitignore 済み）にPMが書く形にします。

## 🔴 プライバシーポリシーのURLが未公開

**Play も App Store も、ストア掲載時に公開URLが必須です。**

草案は `PRIVACY_POLICY_DRAFT.md` にありますが、まだ公開していません。
**Cloudflare Pages に置くのが最短**です（無料・設定済みのアカウントで可）。

**【事業者名】の欄を埋める必要があります。** 個人配信なので、
**氏名または屋号**を入れてください。

# Android：クローズドテストの流れ

## 全体像

```
1. Play Console に登録（$25・本人確認）
        ↓
2. アプリを作成・ストア情報を入力
        ↓
3. AAB をアップロード
        ↓
4. クローズドテストのトラックを作成、テスター12人を登録
        ↓
5. 🔴 12人が「参加」した状態で 14日間連続
        ↓
6. 製品版アクセスを申請 → 審査 → 公開
```

## 1. Play Console 登録

https://play.google.com/console/signup

- **$25（買い切り）**
- **本人確認書類**が必要。審査に数日かかることがあります
- **個人アカウント**を選択

## 2. アプリを作成し、必要事項を入力

**アプリを作るだけでは公開できません。** 以下が全部必要です。

| 項目 | 内容 | 準備状況 |
|---|---|---|
| アプリ名 | `wanote` | ✅ |
| 簡単な説明（80字） | ストア一覧に出る短文 | ❌ 未作成 |
| 詳しい説明（4000字） | ストア詳細ページ | ❌ 未作成 |
| アプリアイコン（512×512） | | ⚠️ 要確認 |
| フィーチャーグラフィック（1024×500） | | ❌ 未作成 |
| スクリーンショット（最低2枚） | | ⚠️ 40枚あるが**3枚が古い** |
| **プライバシーポリシーURL** | | 🔴 **未公開** |
| **データセーフティ** | 何を集めるかの申告 | 🔴 **要記入** |
| コンテンツのレーティング | アンケート形式 | ❌ 未実施 |
| 対象年齢・広告の有無 | **広告ありと申告** | ❌ 未実施 |

> **データセーフティはプライバシーポリシーと一致させてください。**
> 食い違うと審査で指摘されます。`PRIVACY_POLICY_DRAFT.md` の
> 「D. ストアの『データ収集』申告との整合」に、申告すべき項目を
> まとめてあります。

## 3. AAB（App Bundle）をアップロード

上の署名設定が済んだら:

```bash
cd C:\Dev\wanote
flutter build appbundle --release --dart-define-from-file=config/prod.json
```

出力先: `build\app\outputs\bundle\release\app-release.aab`

> **`--dart-define-from-file` を忘れないでください。** 忘れると
> バックエンドURLが埋め込まれず、**AI機能が動きません。**

## 4. テスターを集める

**「テスト」→「クローズドテスト」**でトラックを作り、テスターを登録します。

- **メールアドレスを直接登録**、または **Google グループ**で管理
- **Google グループを推奨**します。人の入れ替えがコンソール操作なしで済みます
- テスターには**オプトインURL**を渡し、**各自が「テストに参加」を押す**必要があります

> 🔴 **「登録した」だけでは数えられません。テスター自身の参加操作が必要です。**

## 5. 🔴 12人 × 14日間

**個人アカウントの新規アプリに課される要件です**（2023年以降）。

- **12人以上**が
- **14日間連続**でテストに参加している状態

**14日は短縮できません。** そのうえで「製品版アクセス」を申請し、
**さらに審査**があります。

### 9/30 締切から逆算

| | |
|---|---|
| 14日間のテスト | 最低2週間 |
| 製品版アクセスの審査 | 数日〜（変動） |
| アプリ自体の審査 | 数日 |

**9月上旬までにクローズドテストを開始**しておくのが安全です。
**テスター12人の確保**も並行して進めてください（家族・友人でも可）。

# iOS：TestFlight

**「同様にテストできないのか」→ できます。しかも制約は緩いです。**

| | Android（Play） | iOS（TestFlight） |
|---|---|---|
| 人数の下限 | **12人必須** | **なし**（1人でも可） |
| 期間の下限 | **14日連続** | **なし** |
| 内部テスター | — | **100人まで・審査なし・即配信** |
| 外部テスター | — | 10,000人まで・**Beta App Review** が必要 |

**iOS の方が、テスト自体はずっと楽です。**

## ただし、ビルドに壁があります

**`flutter build ipa` は Xcode を必要とし、Windows では実行できません。**

そのため **Codemagic**（クラウドCI）を使う方針にしています。

```
Apple Developer Program 承認（年99USD・審査あり）
        ↓
App Store Connect でアプリを作成
        ↓
Codemagic にリポジトリを接続
        ↓
App Store Connect の API キーを Codemagic に登録
        ↓
codemagic.yaml を作成（こちらでやります）
        ↓
CI がビルド → TestFlight へ自動アップロード
        ↓
iPhone の TestFlight アプリで受け取る
```

### iOS 側で追加で必要なもの

| | 状況 |
|---|---|
| Apple Developer Program | 🔴 未申請 |
| App Store Connect のアプリ作成 | 🔴 未 |
| **Sign in with Apple** | 🔴 **未設定。Apple の要件で必須** |
| Codemagic アカウント | 🔴 未 |
| `codemagic.yaml` | 🔴 未作成（**こちらで作ります**） |
| `GoogleService-Info.plist` の Xcode 登録 | 🔴 **Windows では不可。Codemagic 側で対応** |
| 権限説明文（Info.plist） | ✅ 記載済み |
| `SKAdNetworkItems` | 🔴 未（AdMob 登録後） |

> 🔴 **Sign in with Apple は Apple の必須要件です。**
> 「Google など他社のログインを提供するなら、Sign in with Apple も
> 提供しなければならない」というルールがあり、**これが無いと
> iOS はリジェクトされます。** アプリ側の実装は済んでいますが、
> **Apple Developer 側の設定と Firebase 側の設定が未了**です。

# おすすめの進め方

**両方申請したうえで、Android を先に走らせてください。**

理由:

1. **Android は「14日間」という動かせない待ち時間がある**ので、
   早く始めるほど楽
2. **iOS は待ち時間の制約が無い**ので、Codemagic の準備が整い次第
   すぐ配信できる
3. Apple Developer の審査を待つ間に、Android のテストを回せる
