**方針は「実装優先」で進めるが、申請には待ち時間がある**という事実だけ
記録しておく。判断は PM。

## 6. お知らせ機能の設計（PM要望 2026-08-12）

**要望**: 「どれだけお知らせを出すか不明瞭だが、**問い合わせに答えられない
期間**なども考えられる。それを踏まえるとお知らせ機能はあった方がよい」

妥当。**サポートを個人でやる以上、応答できない期間は必ず発生する**。
それを伝える手段が無いと、利用者はメールを送って放置されたと受け取る。
ついでに**プライバシーポリシー改定の周知手段**も同時に解決する
（現状は「Webページに掲載」のみで、アプリ利用者には届かない）。

### 方針：作り込まない。**運用工数ゼロ**の形にする

管理画面は作らない。**Firebase コンソールでドキュメントを1つ書く**だけで
出せる形にする。アプリ側は読むだけ。

```
announcements/{id}
  title_ja, body_ja        必須
  title_en, body_en        任意（無ければ ja にフォールバック）
  publishedAt              この時刻以降に表示
  expiresAt                この時刻を過ぎたら自動で消える（任意）
  important                true なら強調表示（任意）
```

**`expiresAt` が要件の中心**。「8/13〜8/20 は問い合わせ対応をお休みします」は
**期間が過ぎたら自動で消えなければならない**。消し忘れると、
営業しているのに休業中と表示され続ける。

### セキュリティルール

```
match /announcements/{id} {
  allow read: if true;      // 未サインインでも読める
  allow write: if false;    // コンソールからのみ
}
```

**未サインインでも読めるようにする理由**: 障害でサインインできない時こそ
知らせたい。サインイン画面に出せないと意味が半減する。
内容は公開情報なので、読めて困るものではない。

### 表示

| 場所 | 内容 |
|---|---|
| ホーム上部 | 未読のお知らせをバナー表示。閉じられる |
| 設定 →「お知らせ」 | 過去分も含めて一覧（閉じた後も読み返せる） |
| サインイン画面 | `important` のものだけ |

既読は **端末内（SharedPreferences）にID を記録**。サーバに持たない
（既読同期のために書き込みを許すと、ルールを開けることになる）。

**アカウント削除時に既読の記録も消す**こと
（`AuthPrefsKeys.forAccount` に追加）。

### 作らないもの（意図的）

- **プッシュ通知は使わない。** アプリを開いた時に見えれば足りる。
  プッシュを入れると FCM トークンの管理・権限要求・
  プライバシーポリシーの記述が増え、割に合わない
- **管理画面**。コンソールで足りる
- **既読のサーバ同期**。端末ごとに再表示されても実害がない

### 見積もり

読み取り専用・書き込み経路なし・純粋な表示なので**小さい**。
ルール4行、モデル1つ、リポジトリ1つ、画面1つ、バナー1つ、l10n。
リマインダー配線より軽い。
