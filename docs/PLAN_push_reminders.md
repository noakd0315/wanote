# 検討：リマインダーをプッシュ通知にする

作成: 2026-08-13（PM要望「リマインダはプッシュ通知出来たらよいか」）

**状態: 検討中。着手指示待ち。**

---

## 質問への直接の答え

**はい。バックエンドで対象を抽出する形になります。**

```
Cloudflare Cron Trigger（1日1回）
   ↓
全ユーザ横断で「次回予定日が近い記録」を抽出
   ↓
そのユーザの端末トークンを引く
   ↓
FCM HTTP v1 で送信
```

ただし「抽出」は今の Worker にとって**新しい種類の処理**です。
現在の Worker は**呼ばれた本人のデータしか触りません**（uid は検証済み
トークンから取る）。全ユーザを横断して読むのは初めてになります。

---

## 必要になるもの

| # | 内容 | 備考 |
|---|---|---|
| 1 | **Cron Trigger** | Cloudflare Workers の定期実行。**無料プランで使えるかは要確認** |
| 2 | **コレクショングループクエリ** | `prevention_records` / `medications` を全ユーザ横断で検索。**複合インデックスの作成が必要** |
| 3 | **Worker の Firestore クライアント拡張** | 現在は batchGet / commit / listDocuments のみ。**`runQuery`（`allDescendants`）が無い** |
| 4 | **FCMトークンの保管** | `users/{uid}/devices/{token}`。ルール追加、**トークン更新の追従**、**失効トークンの掃除** |
| 5 | **タイムゾーンの保管** | サーバは「その人の朝8時」を知らない。端末は知っている |
| 6 | **APNs キー** | iOS用。**Apple Developer Program が必要**＝申請待ち |
| 7 | **FCM 送信権限** | 既存のサービスアカウントにスコープ追加で足ります |
| 8 | **プライバシーポリシー追記** | **プッシュトークンは端末識別子**。ストアのデータ申告にも追加 |
| 9 | **アカウント削除への追加** | 削除時にトークンも消す（`FirestorePaths` の一覧に追加） |

**4 の「失効トークンの掃除」を忘れると、アンインストールされた端末の
トークンが永久に溜まり続けます。** FCM がエラーを返すので、それを見て
消す処理が要ります。

---

## 正直な比較：今のローカル通知と何が違うか

**先に結論を言うと、リマインダーの用途に限れば、プッシュは
今より良くなりません。**

| | ローカル（実装済み） | プッシュ |
|---|---|---|
| アプリを開かなくても鳴る | ✅ | ✅ |
| 端末を再起動しても残る | ✅ | ✅ |
| **オフラインでも鳴る** | ✅ | ❌ **圏外だと届かない** |
| その人の現地時刻で鳴る | ✅ 端末が時差を知っている | ⚠️ サーバに時差を保存する必要 |
| **別端末での変更が即反映** | ❌ **その端末を開くまで古いまま** | ✅ |
| 運用コスト | ゼロ | Cron＋全件クエリの読み取り課金 |
| iOS に必要なもの | なし | **Apple Developer Program** |

### プッシュで本当に良くなるのは1点だけ

**「別の端末で処方を変えたとき、こちらの端末の予約が古いまま」**という
状態が解消されます。

ただし、この差は**思ったより小さい**です:

- 予約は**数日〜数週間先**の話なので、その間にアプリを一度も開かない
  ことは稀です（開けば即座に組み直されます）
- **同時に2台使う利用者自体が多くない**と想定されます

### プッシュで悪くなる点

**圏外・機内モードだと届きません。** ローカル通知は端末内で完結するので
確実に鳴ります。**飲み忘れ防止という用途では、これは実質的な後退です。**

## 選択肢

### A. 今のまま（ローカルのみ）

追加作業なし。**リマインダーの確実性は最も高い。**

### B. ローカル＋プッシュ併用

両方鳴らすと**二重通知**になるので、どちらかを止める制御が要ります。
複雑さの割に得るものが少なく、**推奨しません**。

### C. プッシュへ全面移行

上の表の 1〜9 が全部必要。**iOS は申請待ちなので着手できません。**
Android だけ先行するとプラットフォーム間で挙動が変わります。

### D. 【折衷案】ローカルのまま、お知らせだけプッシュ

**リマインダーはローカルで確実に鳴らし**、FCM は
「**アプリを開かない人にお知らせを届ける**」用途にだけ使う。

- 全ユーザ横断のクエリが**不要**（お知らせは全員宛の一斉送信）
- Cron も**不要**（お知らせを出したいときに手動で送る）
- 必要なのは 4・6・7・8・9 だけ
- **問い合わせ休止のお知らせが、アプリを開かない人にも届く**

---

## 私の推奨：**D**

理由:

1. **リマインダーはローカルの方が確実**。圏外でも鳴る。飲み忘れ防止という
   目的に対して、プッシュは改善ではなく後退になりうる
2. **お知らせのプッシュは、今の実装では埋められない穴**。
   アプリ内お知らせは開かない人には永久に届かない
3. **全ユーザ横断クエリと Cron が不要**なので、実装量が桁違いに小さい
4. iOS は結局 Apple Developer Program 待ちだが、**Android だけ先に
   動かしても挙動の差が問題になりにくい**（お知らせは即時性が低い）

---

## D を選ぶ場合の作業量

| | |
|---|---|
| FCMトークンの登録・更新・削除 | 中 |
| Firestore ルール（`users/{uid}/devices`） | 小 |
| Worker の送信ルート（`POST /admin/announce`） | 中。**管理者しか叩けない認可が必須** |
| プライバシーポリシー・データ申告の追記 | 小 |
| アカウント削除への組み込み | 小 |
| iOS の APNs 設定 | **申請待ち** |

> **送信ルートの認可設計に注意が必要です。** 誰でも叩けると
> **全ユーザに任意の通知を送れる**ことになります。Worker のシークレットに
> 管理用トークンを置き、それを持つ人だけが送れる形にします。
